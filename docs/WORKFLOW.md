# User Workflow

บอทใช้ `/start` เป็นจุดเริ่มเดียว แล้วแยกผู้ใช้ตามเป้าหมาย ไม่บังคับให้เลือกมหาวิทยาลัยก่อน

```mermaid
flowchart TD
    A[/start] --> B{ต้องการอะไร}
    B --> C[ยังไม่รู้จะเรียนอะไร]
    B --> D[รู้มหาวิทยาลัยแล้ว]
    B --> E[เช็ก GPAX]
    B --> F[เปรียบเทียบ 2-3 หลักสูตร]
    B --> G[รายการโปรด]
    C --> H[กรอกข้อมูล 5 ข้อ]
    H --> I[ผลลัพธ์เรียงตามสถานะ]
    D --> J[มหาวิทยาลัย > วิทยาเขต > คณะ > สาขา > โครงการ]
    J --> J2[หรือ ดูโครงการทั้งหมดของมหาวิทยาลัย]
    E --> K[สาย > GPAX > มหาวิทยาลัย > ผลตรวจ]
    I --> L[เปิดการ์ดโครงการ]
    J --> L
    K --> L
    F --> L
    G --> L
    L --> M[สมัครได้ไหม / ปิดรับ / ต้องเตรียมอะไร]
    M --> N[Rule Trace / Portfolio / Checklist / Favorite / Reminder]
```

## หลักการของหน้าจอ

- การ์ดผลลัพธ์ต้องบอกสถานะ วันปิดรับ และสิ่งที่ต้องทำต่อก่อนรายละเอียดเชิงลึก
- การ์ดโครงการต้องมีสรุปเร็ว 3 อย่าง: สมัครได้ไหม, ปิดรับเมื่อไร, ต้องทำอะไรต่อ
- รายการโครงการต้องติดป้าย `ยืนยันแล้ว`, `รอประกาศ`, `ข้อมูลปีก่อน` หรือ `ต้องตรวจเพิ่ม`
- ผลตรวจใช้คำว่า `ผ่าน`, `ไม่ผ่าน`, `ต้องตรวจเพิ่ม`, `ไม่มีข้อมูล` พร้อมเหตุผล
- ข้อมูลที่ไม่มีในประกาศจะแสดงว่าไม่ระบุ ไม่เติมจากการคาดเดา
- ถ้ามีตัวเลือกเดียวให้ข้ามเมนูนั้นอัตโนมัติ
- ทุกหน้ามีทางกลับหน้าเริ่มต้น และหน้าโครงการไม่แสดงตัวเลือกสาขาซ้ำ

## ขอบเขตคำถาม

`/ask` รองรับคำถามเรื่องวันสมัคร Portfolio เอกสาร GPAX ค่าเรียน และสัมภาษณ์ โดยจับคู่กับชื่อมหาวิทยาลัย/สาขาและตอบจาก project ที่มี source เท่านั้น หากจับคู่ไม่ได้ ระบบจะให้กลับไปใช้ `/tcas_search` แทนการเดาคำตอบ
