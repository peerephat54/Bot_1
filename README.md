# Bot Portfolio TCAS

บอท Discord สำหรับช่วยนักเรียนค้นหาและวางแผนสมัครมหาวิทยาลัยรอบ Portfolio โดยรวมข้อมูลหลักสูตร โครงการ คุณสมบัติ Portfolio เอกสาร ค่าใช้จ่าย และกำหนดการไว้ในขั้นตอนเดียว

## ปัญหาที่แก้

นักเรียนจำนวนมากยังไม่รู้ว่าจะเริ่มจากมหาวิทยาลัยหรือสาขาใด การเปิดเว็บไซต์และ PDF หลายแห่งทำให้พลาดเงื่อนไขหรือวันสมัคร บอทจึงมีสองทางเข้า:

- `/start` สำหรับคนที่ยังไม่รู้ว่าจะเรียนอะไร กรอก GPAX วุฒิ/แผน ผลงาน ภาษา พื้นที่ และงบ แล้วดูรายการที่ควรตรวจต่อ
- `/tcas_search` สำหรับคนที่รู้มหาวิทยาลัยแล้ว และค้นตาม University → Campus → Faculty → Major → Project
- `/grade_check` สำหรับเทียบ GPAX แยกเป็นคำสั่งสั้น ๆ โดยเลือกสายวิศวกรรมศาสตร์ วิทยาศาสตร์ เทคโนโลยีสารสนเทศ หรือเกมและสื่อดิจิทัล
- `/favorites` และปุ่ม `Checklist` สำหรับบันทึกโครงการและติดตามสิ่งที่ต้องเตรียม
- `/deadlines` สำหรับดูวันปิดรับสมัครและวันสัมภาษณ์ที่ใกล้ถึงจากวันที่ระบุจริงใน dataset
- `/my_plan` สำหรับรวมโครงการโปรด ความคืบหน้า Checklist และวันปิดรับไว้ในหน้าเดียว
- `/ask` สำหรับคำถามภาษาปกติที่ตอบจากข้อมูลใน dataset เท่านั้น โดยสรุปคำถามหลายประเด็นได้พร้อมกันสูงสุด 3 หัวข้อ และแสดงสถานะแหล่งข้อมูลตามวันที่ตรวจจริง
- `/feedback` สำหรับส่งปัญหา ข้อมูลที่ควรแก้ หรือข้อเสนอแนะ โดยเก็บในไฟล์ local ที่ไม่ถูก commit

หลังเลือกมหาวิทยาลัยจะมีปุ่ม **ดูโครงการทั้งหมดของมหาวิทยาลัย** เพื่อข้ามการไล่ผ่านคณะและสาขาได้ โดยยังแสดงชื่อสาขาและสถานะของแต่ละโครงการ

หน้าเริ่มต้นใช้ภาษาการใช้งานปกติ แบ่งเป็น **ค้นหาตามมหาวิทยาลัย**, **ค้นหาจากข้อมูลของฉัน**, **ตรวจ GPAX**, **เปรียบเทียบหลักสูตร** และ **รายการโปรด** เพื่อให้ผู้ใช้เลือกทางเข้าได้ทันที โดยไม่ต้องเริ่มจากการคุยกับ AI

คำสั่ง `/deadlines` จะไม่แปลงข้อมูลที่ระบุเพียงเดือนหรือมีวันที่ขัดแย้งให้เป็นวันจริง ส่วน `/my_plan` จะแสดงเฉพาะโครงการที่ผู้ใช้บันทึกไว้ และจะแจ้งตรง ๆ หากโครงการนั้นไม่อยู่ใน dataset ปัจจุบัน

วิธีใช้แบบเต็มควรประกาศให้ผู้ใช้จากข้อความแนะนำในเซิร์ฟเวอร์ โดยไม่เพิ่มคำสั่ง
แยกสำหรับ dashboard ภายในหรือคำอธิบายที่ไม่จำเป็นต่อการสมัคร

## คำตอบที่การ์ดโครงการต้องให้ได้

การ์ดแรกจะแสดงตามลำดับที่นักเรียนต้องใช้ตัดสินใจ:

1. สรุปเร็ว: สมัครได้ไหม, ปิดรับสมัครเมื่อไร และต้องทำอะไรต่อ
2. ผลตรวจรายเงื่อนไข: ผ่าน, ไม่ผ่าน, ต้องตรวจเพิ่ม หรือไม่มีข้อมูล
3. ต้องเตรียมอะไรต่อ เช่น วุฒิ รายวิชา คะแนน Portfolio และเอกสาร
4. วันเปิดรับสมัคร วันปิดรับสมัคร วันประกาศผู้มีสิทธิ์สัมภาษณ์ วันสัมภาษณ์ และวันประกาศผลเท่าที่มีในแหล่งทางการ
5. ป้ายสถานะข้อมูล: ยืนยันแล้ว, รอประกาศ, ข้อมูลปีก่อน หรือ ต้องตรวจเพิ่ม
6. ลิงก์ประกาศต้นทางและวันที่ตรวจข้อมูลล่าสุด

ใน `/ask` สถานะ `ยืนยันแล้ว` จะใช้เมื่อมีประกาศทางการและตรวจภายใน 7 วันเท่านั้น หากเกินกำหนดจะแสดง `ควรตรวจซ้ำ` และหากไม่มีวันที่ตรวจจะแสดง `รอตรวจ` เพื่อไม่ให้ผู้ใช้เข้าใจว่าข้อมูลเก่าคือข้อมูลยืนยันปัจจุบัน

ผล “ผ่าน” หมายถึงผ่านเฉพาะข้อมูลที่ตรวจด้วยกฎได้ ไม่ใช่การรับรองสิทธิ์สมัคร หากข้อมูลไม่พอ ระบบจะแสดง “ต้องตรวจเพิ่ม” หรือ “ไม่มีข้อมูล” และไม่เติมข้อมูลเอง

## การออกแบบเชิงวิศวกรรม

ข้อมูลถูกแยกเป็นมหาวิทยาลัย วิทยาเขต หลักสูตร โครงการ เกณฑ์ และ timeline พร้อม source audit และ validation การตัดสินใจไม่ใช้การเดาของ AI แต่ใช้ deterministic Rule Engine ที่คืนผลรายเงื่อนไขและเหตุผล

ฟีเจอร์ใช้งานซ้ำประกอบด้วยรายการโปรด Checklist เตือนก่อนปิดรับประมาณ 3 วัน และการเปรียบเทียบ 2–3 หลักสูตร ระบบเก็บข้อมูลผู้ใช้ไว้ใน `tmp/user_features.json` สำหรับ deployment ปัจจุบัน และมี schema สำหรับย้ายไป Supabase ใน `migrate_user_features.sql`

ดูรายละเอียดได้ที่ [Architecture และ Data Flow](docs/ARCHITECTURE.md), [Workflow ผู้ใช้](docs/WORKFLOW.md), [ขั้นตอนตรวจและนำเข้า Supabase](docs/SUPABASE_DATASET_IMPORT.md) และ [แผนทดสอบผู้ใช้](docs/USER_TEST_PLAN.md)

## แหล่งข้อมูลและการอัปเดต

ใช้เว็บไซต์มหาวิทยาลัย คณะ และระบบ TCAS เป็นแหล่งหลัก ข้อมูลปีก่อนจะแสดงเป็นข้อมูลอ้างอิงเท่านั้น ไม่ปะปนกับเกณฑ์ปีปัจจุบัน

ตรวจแหล่งข้อมูลตามรอบด้วย:

```powershell
python scripts/check_official_sources.py --report-path tmp/source-monitor-report.json
```

GitHub Actions จะเรียกตรวจทุกวันและแจ้งเมื่อ link ใช้ไม่ได้หรือข้อมูลเก่ากว่ากำหนด การตรวจนี้ไม่คัดลอกข้อความเว็บเข้า dataset อัตโนมัติ เพราะการเปลี่ยนเกณฑ์ต้องมีคนตรวจและรัน importer ก่อน

ตรวจความถูกต้องของ dataset ด้วย:

```powershell
python scripts/validate_dataset.py
```

ใน Discord ใช้ `/data_quality` ดู coverage, คิวตรวจ และ Source Trust; ใน Evidence Review Queue เลือกดูเฉพาะเนื้อหาที่เปลี่ยน ข้อมูลเกิน 7 วัน หรือรายการที่ไม่มี baseline ได้ ใช้ `/health` แยกสถานะบอท, Supabase, Source Trust และ fingerprint ของชุดข้อมูลที่ซิงก์ล่าสุด การตรวจ hash ไม่ใช่การรับรองว่าเนื้อหาประกาศไม่เปลี่ยนหลังเวลาตรวจ

Source Trust แสดงผลตรวจเว็บสดล่าสุดแยกจาก dataset snapshot: จำนวนแหล่งที่เปิดได้ แหล่งที่ผิดพลาด แหล่งที่เกิน 7 วัน แหล่งที่เนื้อหาเปลี่ยน และรายการที่ต้องให้คนตรวจ ก่อนนำข้อมูลใหม่เข้า Supabase

### Workflow อัปเดตข้อมูลรายวัน

1. สร้างรายงานตรวจเว็บสดด้วย `python scripts/verify_import_truth.py --output tmp/import_truth_report.json`
2. เปิด `/data_quality` แล้วใช้ Evidence Review Queue ดูรายการที่เนื้อหาเปลี่ยน เกิน 7 วัน หรือไม่มี baseline
3. เปิดเว็บทางการเทียบวันสมัคร เกณฑ์ และจำนวนรับด้วยคน ก่อนแก้ `datasets/tcas70_admissions.json` หรือ `tcas70_source_audit.json`
4. รัน `python scripts/validate_dataset.py` และ `python scripts/import_supabase_dataset.py` แบบ dry run
5. นำเข้า Supabase ได้ต่อเมื่อ evidence gate ผ่านเท่านั้น หากยังเป็น `needs_review` ให้คงข้อมูลเดิมและรอตรวจต่อ

## ติดตั้งและรันในเครื่อง

ต้องมี Python และค่าต่อไปนี้ใน `.env`:

```text
DISCORD_BOT_TOKEN=...
SUPABASE_URL=...
SUPABASE_KEY=...
```

ติดตั้ง dependency จาก `requirements.txt` แล้วรัน:

```powershell
python Bot_Portfolio.py
```

ถ้าต้องการเปิดบอทจากเครื่องที่บอทหยุดอยู่ ให้ใช้ตัวเริ่มระบบที่มี watchdog:

```powershell
python scripts/start_bot.py
```

เมื่อบอทออนไลน์แล้ว สมาชิกทั่วไปใช้ `/startbot` เพื่อเปิด watchdog ได้ ระบบจะพยายามเปิดโปรเซสใหม่เมื่อบอทหลุด และจะไม่เปิด watchdog ซ้ำ แต่คำสั่งนี้ไม่สามารถใช้ปลุกบอทที่ออฟไลน์สนิทได้ เพราะ Discord จะส่งคำสั่งไม่ได้ในสถานะนั้น

ห้าม commit `.env` หรือ token ลง GitHub หาก token เคยถูกเปิดเผย ให้ยกเลิกและสร้าง token ใหม่ทันที

## ผลการตรวจปัจจุบัน

- Automated regression tests: ตรวจด้วย `python -m unittest discover -s tests -p "test_*.py"` (จำนวนอาจเปลี่ยนตามฟีเจอร์)
- Dataset validation: ใช้ตรวจจำนวนแถว ความสัมพันธ์ ปีการศึกษา สถานะแหล่งข้อมูล และข้อจำกัดของ timeline
- Runtime: บอทซิงก์ slash commands และเชื่อม Discord ได้จากการทดสอบล่าสุด
- การใช้งานจริง: ผู้พัฒนารายงานว่ามีผู้ใช้ 49 คน ณ 13 ก.ย. 2569; การทดสอบกับนักเรียนแบบมีภารกิจมี 21 คนตามรายงานก่อนหน้า (เป็นคนละตัวเลข) แต่ยังไม่มีผลสรุปเวลา อัตราทำภารกิจสำเร็จ และจุดสับสนจนกว่าจะบันทึกผลใน `docs/USER_TEST_PLAN.md`

## ข้อจำกัดที่ประกาศให้ผู้ใช้ทราบ

- coverage ยังจำกัดเฉพาะมหาวิทยาลัยและหลักสูตรที่อยู่ใน dataset
- บางโครงการมีเพียงข้อมูลหลักสูตรหรือข้อมูลปีก่อน จึงยังยืนยันสิทธิ์สมัครปีปัจจุบันไม่ได้
- เงื่อนไขวุฒิ รายวิชา ผลงาน คะแนน และเอกสารบางแบบต้องตรวจจากประกาศฉบับเต็ม
- วันสมัครและกำหนดการอาจเปลี่ยนหลังการตรวจ ระบบจึงแสดงวันที่ตรวจและลิงก์ต้นทางทุกครั้ง
