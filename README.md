# Bot Portfolio TCAS

บอท Discord สำหรับช่วยนักเรียนค้นหาและวางแผนสมัครมหาวิทยาลัยรอบ Portfolio โดยรวมข้อมูลหลักสูตร โครงการ คุณสมบัติ Portfolio เอกสาร ค่าใช้จ่าย และกำหนดการไว้ในขั้นตอนเดียว

## ปัญหาที่แก้

นักเรียนจำนวนมากยังไม่รู้ว่าจะเริ่มจากมหาวิทยาลัยหรือสาขาใด การเปิดเว็บไซต์และ PDF หลายแห่งทำให้พลาดเงื่อนไขหรือวันสมัคร บอทจึงมีสองทางเข้า:

- `/start` สำหรับคนที่ยังไม่รู้ว่าจะเรียนอะไร กรอก GPAX วุฒิ/แผน ผลงาน ภาษา พื้นที่ และงบ แล้วดูรายการที่ควรตรวจต่อ
- `/tcas_search` สำหรับคนที่รู้มหาวิทยาลัยแล้ว และค้นตาม University → Campus → Faculty → Major → Project
- `/grade_check` สำหรับเทียบ GPAX แยกเป็นคำสั่งสั้น ๆ โดยเลือกสายวิศวกรรมศาสตร์ วิทยาศาสตร์ หรือเทคโนโลยีสารสนเทศ
- `/help` สำหรับคำอธิบายศัพท์และข้อจำกัดของผลคัดกรอง

## คำตอบที่การ์ดโครงการต้องให้ได้

การ์ดแรกจะแสดงตามลำดับที่นักเรียนต้องใช้ตัดสินใจ:

1. สมัครได้ไหมในระดับคัดกรองเบื้องต้น
2. ผลตรวจรายเงื่อนไข: ผ่าน, ไม่ผ่าน, ต้องตรวจเพิ่ม หรือไม่มีข้อมูล
3. ต้องเตรียมอะไรต่อ เช่น วุฒิ รายวิชา คะแนน Portfolio และเอกสาร
4. วันเปิดรับสมัคร วันปิดรับสมัคร วันประกาศผู้มีสิทธิ์สัมภาษณ์ วันสัมภาษณ์ และวันประกาศผลเท่าที่มีในแหล่งทางการ
5. ลิงก์ประกาศต้นทางและวันที่ตรวจข้อมูลล่าสุด

ผล “ผ่าน” หมายถึงผ่านเฉพาะข้อมูลที่ตรวจด้วยกฎได้ ไม่ใช่การรับรองสิทธิ์สมัคร หากข้อมูลไม่พอ ระบบจะแสดง “ต้องตรวจเพิ่ม” หรือ “ไม่มีข้อมูล” และไม่เติมข้อมูลเอง

## การออกแบบเชิงวิศวกรรม

ข้อมูลถูกแยกเป็นมหาวิทยาลัย วิทยาเขต หลักสูตร โครงการ เกณฑ์ และ timeline พร้อม source audit และ validation การตัดสินใจไม่ใช้การเดาของ AI แต่ใช้ deterministic Rule Engine ที่คืนผลรายเงื่อนไขและเหตุผล

ดูรายละเอียดได้ที่ [Architecture และ Data Flow](docs/ARCHITECTURE.md) และ [แผนทดสอบผู้ใช้](docs/USER_TEST_PLAN.md)

## แหล่งข้อมูลและการอัปเดต

ใช้เว็บไซต์มหาวิทยาลัย คณะ และระบบ TCAS เป็นแหล่งหลัก ข้อมูลปีก่อนจะแสดงเป็นข้อมูลอ้างอิงเท่านั้น ไม่ปะปนกับเกณฑ์ปีปัจจุบัน

ตรวจแหล่งข้อมูลตามรอบด้วย:

```powershell
python scripts/check_official_sources.py --report-path tmp/source-monitor-report.json
```

GitHub Actions จะเรียกตรวจทุกวันและแจ้งเมื่อ link ใช้ไม่ได้หรือข้อมูลเก่ากว่ากำหนด การตรวจนี้ไม่คัดลอกข้อความเว็บเข้า dataset อัตโนมัติ เพราะการเปลี่ยนเกณฑ์ต้องมีคนตรวจและรัน importer ก่อน

ตรวจความถูกต้องของ dataset ด้วย:

```powershell
python scripts/validate_dataset.py
```

## ติดตั้งและรันในเครื่อง

ต้องมี Python และค่าต่อไปนี้ใน `.env`:

```text
DISCORD_BOT_TOKEN=...
SUPABASE_URL=...
SUPABASE_KEY=...
```

ติดตั้ง dependency จาก `requirements.txt` แล้วรัน:

```powershell
python Bot_Portfolio.py
```

ห้าม commit `.env` หรือ token ลง GitHub หาก token เคยถูกเปิดเผย ให้ยกเลิกและสร้าง token ใหม่ทันที

## ผลการตรวจปัจจุบัน

- Automated regression tests: ผ่าน 54 รายการ
- Dataset validation: ใช้ตรวจจำนวนแถว ความสัมพันธ์ ปีการศึกษา สถานะแหล่งข้อมูล และข้อจำกัดของ timeline
- Runtime: บอทซิงก์ slash commands และเชื่อม Discord ได้จากการทดสอบล่าสุด
- User testing: log เดิมมีสัญญาณการใช้งาน แต่ยังรวมบัญชีทดสอบ จึงยังไม่นับเป็นนักเรียนจริง 10–20 คน ต้องเก็บตามแบบฟอร์มใน `docs/USER_TEST_PLAN.md` ก่อนสรุปผล

## ข้อจำกัดที่ประกาศให้ผู้ใช้ทราบ

- coverage ยังจำกัดเฉพาะมหาวิทยาลัยและหลักสูตรที่อยู่ใน dataset
- บางโครงการมีเพียงข้อมูลหลักสูตรหรือข้อมูลปีก่อน จึงยังยืนยันสิทธิ์สมัครปีปัจจุบันไม่ได้
- เงื่อนไขวุฒิ รายวิชา ผลงาน คะแนน และเอกสารบางแบบต้องตรวจจากประกาศฉบับเต็ม
- วันสมัครและกำหนดการอาจเปลี่ยนหลังการตรวจ ระบบจึงแสดงวันที่ตรวจและลิงก์ต้นทางทุกครั้ง
